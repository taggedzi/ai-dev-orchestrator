## Prepared local gate

`control_policy.py` is a separate admission layer, not a change to the existing fault proxy. It authenticates a control credential that differs from the disposable backend key; the private control value is never forwarded. It permits only fixed conversation routes with matching HTTP methods, canonical bounded pagination, and exact operation/body hashes. Creation must match the full frozen canonical request, including the restrictive tool configuration. Extra fields, duplicate JSON keys, unknown headers, WebSocket upgrades and broad server/MCP/settings routes are refused before forwarding.

SQLite WAL/FULL records a possible-send before each authorized mutation. Transaction serialization prevents two connections from admitting concurrent work. Replay and an unresolved earlier mutation hold further work across a restart. Fencing/expiry blocks new work while a separately granted interrupt/pause can still be issued and recorded. Read lookups stay bounded at 128 for this preparation profile. Responses supply observations, never task acceptance. A lost acknowledgement remains uncertain and is never retried automatically.

The gate's local transport binds loopback and forwards to one literal loopback address. It is conformance preparation, not yet a deployed guard service or a transport for the target VM. Native response pagination, route/schema compatibility and required WebSocket recording remain to measure. A durable admission fence does not cancel an already admitted/in-flight request; independent network/stream fencing, broker permit revocation and OS stop remain mandatory. The developer has [selected the guard topology for preparation](../../docs/decisions/0001-validation-network-boundary.md); native provisioning and final tests still need separate concrete review.

## Read-only SDK check to run

`control_schema_probe.py` is designed to execute only inside the existing pinned image. Give it the synthetic proposed request on stdin. It checks that every supplied request/agent/LLM/context/workspace field is recognized (rather than silently ignored), validates the native request model, verifies restrictive settings, and emits the two action schemas plus native request schema. It does not construct a Conversation or tool executor, send a message, run a task, or call inference.

The concrete action briefly starts installed Docker Desktop, verifies the existing image identity, and runs only this probe in a new network-none, non-root, read-only container with dropped capabilities, no-new-privileges, bounded tmpfs, 1 CPU/2 GiB/no extra swap and 128 PIDs. No host mount or published port is included; input/code travel through process stdin/argv. Save raw output/error and source hashes. Stop/remove that container and restore Desktop's stopped state if no unrelated work is running. No image pull, package installation or image rebuild is authorized by this metadata check. A rejected field is retained as a result and corrected in a new explicit request revision.
