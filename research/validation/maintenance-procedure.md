## Measured inputs and review coverage

The one-use archive reader captured **327 control components and 282 selected maintenance payload files** from all 114 verified archives: 1,145,542 bytes of text. The controls include 133 preinst/postinst/prerm/postrm/config scripts. All 228 dpkg-deb commands exited zero without timeout. Tar streams were read as data; selected text was saved under fixed component names or hash-derived filenames, never by using archive paths as output destinations. No downloaded script or binary executed.

The first archive attempt retained 103 complete packages before rejecting valid escaped systemd slice filenames. Read-only listing identified `system-systemd\x2dcryptsetup.slice` and `system-systemd\x2dveritysetup.slice`. A new attempt accepts backslashes as POSIX filename data, while continuing to reject absolute/parent paths. These names never become shell arguments or filesystem output paths. The first source/result remains intact.

A separate read-only check confirmed the source VM powered off with all eight NICs disabled before and after inspection. It compared **all 33,230,422,016 bytes** of the retained sparse filesystem view, including unallocated zero ranges, against the source VDI mapping. Source disk SHA-256 stayed `2eb1d9cd009ecfe83381d855137f5cee8c1317739f6209beddd6da8a10955a09`; view SHA-256 is `e4dd0dd3f222707c8b8203b3553257c8bcb52ec45c04ff308a1d35cf65f430a8`. Allocated-range identity matches the earlier export receipt. Nothing was mounted, replayed or written to either input.

Read-only debugfs then captured **274 installed script/helper/configuration files**, selecting the 97 upgraded packages and existing trigger/helper owners. A follow-up captured 34 helper/APT-hook files, including repeats. Both runs rehashed the complete view afterward and preserved WSL's actual dpkg status. There were 647 successful debugfs commands across these two runs; expected missing-path diagnostics are recorded. The first baseline attempt could not locate debugfs in its restricted PATH and started no reader; the corrected attempts name `/usr/sbin/debugfs` explicitly. Raw sources, commands, files, hashes and held attempts are bound in [maintenance evidence](maintenance-evidence.json).

This is complete capture of the selected inputs and a review of the critical paths below. It is not a proof of every transitive helper, runtime branch, service effect or security property. Dpkg can execute the **installed older** prerm/postrm during upgrade, so collecting only new archives would have left an important gap. Debian's [dpkg manual](https://manpages.debian.org/bookworm/dpkg/dpkg.1.en.html) describes that sequence; the installed source files provide the version-specific evidence here.

## Findings that change the procedure

| Source observation | Required control or consequence |
| --- | --- |
| libc6 `2.39-0ubuntu8.12` postinst directly calls `systemctl daemon-reexec`. Systemd `255.4-1ubuntu8.19` can re-exec PID 1/user managers and directly try-restart networkd/journald. | Permit these trusted maintenance effects explicitly. Run the transaction as a root-owned system service with retained logs, independent of the operator's user manager. Keep the external VM lease authoritative. Console acknowledgement loss remains an uncertain result requiring reconciliation. |
| needrestart `3.6-7ubuntu4.6` installs a Post-Invoke hook using Ubuntu mode; its source can select automatic restart despite a noninteractive frontend. Both old/new apt-pinvoke recognize `NEEDRESTART_SUSPEND`. | Use a fresh APT configuration with no inherited hooks; also set `NEEDRESTART_SUSPEND=1` and `NEEDRESTART_MODE=l`. These settings do not suppress other packages' direct systemctl calls. |
| cloud-init `26.2` config has a conditional wget/curl metadata lookup; disabled service units/marker do not guard that script path. | Keep physical VM NICs disabled throughout. Noninteractive configuration is not a network boundary. |
| Installed APT hooks include PackageKit D-Bus notification, AppStream refresh, debconf preconfiguration and an apt-frontend snap advisory hook. APT periodic updates are enabled in the baseline. | Use empty private APT configuration/source/preference/hook directories, signed file-only sources, and quiesce/mask automatic actors. Dpkg scripts/triggers remain active. Recheck the actual effective configuration before applying anything. |
| Installed init-system-helpers `1.66ubuntu1` unmask removes a `/dev/null` link only when its own masked-state file exists. That state directory and policy-rc.d are absent in the inspected baseline. | Create policy-rc.d only if absent. Before relying on each persistent administrator mask, reject existing helper masked state or nonmatching admin overrides; do not erase helper state. Verify mask survival after the transaction. Source review does not substitute for a target test. |
| New kernel scripts invoke depmod/run-parts. Installed hooks create initramfs, update boot links/GRUB, possibly notify shim and record reboot-required. The unattended-upgrades kernel hook is a notifier, rather than an authorization to run a general upgrade. | Reserve space, keep old kernels and preserve logs. Do not suppress triggers, claim the new kernel is already running, or reboot automatically. Boot/readiness remains a separate approved stage. |
| Docker/containerd/NFT services have activation paths; AppArmor profile parsers can run directly and some failures are ignored. | Keep engine/socket or stock NFT units masked, with no experiment dispatch. Installed-package success never proves enforcing AppArmor, packet policy or runtime readiness. |

## Proposed sequence for the later approved runner

1. **Bind and preserve the target.** Resolve the separate guard creation decision first and preserve the original clone source. Bind actual VM/disk identities, independently restorable baselines, original 480-row status, media/runner hashes, approved security/currentness disposition and action authority. Require all NICs off and no host shares. Refuse pre-existing partial transaction state. This stage has not created the guard or a restore disk.
2. **Check the maintenance window.** Keep the existing 600-second host lease. Proposed guest transaction limit is 210 seconds, stop grace 10 seconds, postcondition budget 20 seconds and external stop budget 10 seconds. Start the transaction only with at least 250 seconds remaining. These are refusal thresholds, not measured installation duration. Insufficient time means a hold; no extension, renewal or automatic retry is authorized.
3. **Prepare within the disconnected guest.** Require the proposed free-space thresholds: 4 GiB at root, 512 MiB at boot and 64 MiB at EFI, considering shared filesystem accounting. Quiesce package/update actors, record prior unit/override state, create the reviewed policy and persistent role masks without overwrites, and keep background actors fenced. The JSON lists the specific units; existing unexpected units, active snaps or unknown activation paths require review.
4. **Use actual installation state.** The new APT configuration must have `Dir=/`, actual guest `/var/lib/dpkg/status`, actual `/usr/bin/dpkg`, private metadata/cache and empty private APT main/parts/preferences/sourceparts/trustedparts directories. Never reuse the planner's configuration or copied `target-status`. Clear `DPKG_ROOT`/`DPKG_ADMINDIR`; reject alternate roots or unexpected dpkg hooks/options. Use the normal guest dpkg configuration only after inspecting it. Critical final options and an `apt-config dump` must prove this effective setup before refresh or simulation. Native generation/refusal checks for this fresh configuration are still to prepare.
5. **Verify before mutation.** Refresh only the mounted signed file mirror, require the frozen signatures/indexes, repeat the exact role simulation against live guest status, and check every printed URI/pool identity and archive SHA-256. The [APT manual](https://manpages.ubuntu.com/manpages/noble/man8/apt-get.8.html) notes that print-uris filenames can differ from publisher paths; its printed MD5 is not the archive authenticity check. Require exclusive maintenance ownership and actual APT/dpkg locking. No generic upgrade, autoremove, fix-broken or unauthenticated override is allowed.
6. **Apply once under explicit authority.** The JSON contains all exact role pins and proposed argv. Use `DEBIAN_FRONTEND=noninteractive`, `UCF_FORCE_CONFFOLD=1` and dpkg `--force-confold` to retain locally modified configuration, while preserving generated side files for review. [Ucf documents its environment control](https://manpages.ubuntu.com/manpages/noble/man1/ucf.1.html); dpkg's conffile handling is separate. The root service proposes `Type=exec`, `RuntimeMaxSec=210s`, `TimeoutStopSec=10s`, `KillMode=control-group`, `Restart=no`. [Noble's systemd service manual](https://manpages.ubuntu.com/manpages/noble/man5/systemd.service.5.html) describes these service settings; target behavior through reexec remains unmeasured. No blanket service-suppression claim is made.
7. **Collect, stop and review.** Require empty dpkg-audit output, fully installed states, no pending/awaited triggers, exact expected name/version maps (496 executor / 489 guard), preserved masks/helper-state constraints, inactive protected runtimes/sockets and unchanged NIC disconnection. Retain real status bytes, logs and conffile/ucf side files. Power off within the original outside-VM deadline. On timeout, changed effects or uncertain evidence, fence, confirm stop and retain partial state for restoration review; never replay or repair automatically. New-kernel boot, credentials/machine identity, enforcing LSM, image import and final isolation/routing/recovery remain separate gates.

The original mirror still includes its original contract SHA-256 `65a3ea41e793c082e9357cd57a81e1c30f72fd1d94fdbafd8c91732d20614f4a`; it has not been rewritten to include this later proposal. Next: prepare a read-only maintenance media artifact and native-checked configuration/runner preview. Actual guard disk bindings, installation timing, reexec/console behavior, approvals and final qualification remain open.
