# Prepared broker phase ceiling

The developer approved [decision 0002](../../docs/decisions/0002-fixture-phase-output-boundary.md)
for preparation on November 22. The local scripted broker now has an explicit
`phase-ceiling-v1` mode. Default `strict` still rejects oversized requests and
preserves the original strict transcript binding digest.

## Exact policy and request bindings

Ceiling mode requires a separate approval reference and freezes that reference,
mode and transcript into a distinct policy digest. Each row adds:

```json
"normalization": {
  "effective_request_sha256": "<independently frozen effective body hash>",
  "incoming_counter_evidence_sha256": "<incoming count evidence hash>"
}
```

The existing admission's `counter_evidence_sha256` binds the effective request's
input/response count evidence. These are trusted declarations requiring later
qualification, not tokenizer attestations generated by the broker.

The incoming raw hash must match the next frozen transcript row and one-use
permit. Only `max_completion_tokens` may change, to the smaller of the incoming
limit and the trusted role cap. Values outside 1..6,000, conflicting output fields,
unknown fields and invalid stream/message shapes refuse. A request already within
its cap keeps its original bytes. A changed request retains native key/array order
and content strings in compact UTF-8; its exact effective hash must match.

The effective body then passes all existing strict role/count/response checks.
The permit still binds the incoming bytes and full original money envelope. One
transaction journals raw/effective hashes, both count references,
requested/effective limits, trusted phase and possible-send before selecting a
scripted response. Journal failure rolls the admission and possible-send back
together. No response/tool argument is truncated. An interrupted reply retains
unknown spend and cannot gain another permit after restart.

The prepared CLI is:

```powershell
python -m research.validation broker DATABASE TRANSCRIPT --port PORT --output-policy phase-ceiling-v1 --ceiling-approval "<scoped preparation approval>"
```

It remains a loopback synthetic service with no provider-forwarding implementation.
This command does not approve a frozen deployment or executor run.

## Measurements and remaining work

All eight new ceiling tests passed, alongside the nine strict phase tests and
three byte-review tests. They cover every role cap, smaller requests, required
policy/approval/bindings, raw/effective drift, role/permit mismatch, restart,
interruption, journal failure and unchanged strict binding.

The integrated admission path also reproduced all four retained native prepared
request captures against their independently retained effective bodies. Finish
changes 6,000 to 1,000; initial edit remains unchanged. This reused earlier native
input estimates and a declared synthetic response count of one. No new tokenizer,
Agent step, tool action or inference ran. These comparisons do not qualify actual
finish traffic or response counts. See [evidence](broker-ceiling-evidence.json).

The final full regression passed 339 tests with 13 platform skips; Ruff passes.
Freeze qualified complete input/response counts and actual Agent Server traffic on
the final target before native dispatch. Guard services, stream fencing, route
metering, isolation and recovery remain separate qualification work.
