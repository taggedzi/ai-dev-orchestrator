### Minimal fixture probe

[executor-recovery-probe.py](fixtures/executor-recovery-probe.py) is a Linux, standard-library marker writer for the fault variants. Freeze its hash and mount it read-only at `/fixture/executor-recovery-probe.py`. Precreate an empty regular `/fixture-effect/markers.log` in a bounded disposable scratch volume. Keep `/fixture-control` read-only to the guest. The trusted gate publisher uses atomic replacement of `release` with the operation UUID and LF. Mount backing paths and qualify the live observer on the same #12 profile. The probe requires an independently watched scratch disk or isolated observer outside the executor's control and trusted final collection from the stopped disk. A live tool message is insufficient as a barrier.

```sh
python3 -I /fixture/executor-recovery-probe.py append <effect-operation-uuid>
python3 -I /fixture/executor-recovery-probe.py cancel <effect-operation-uuid>
```

Both write and fsync an `effect` line. In `append` mode the process holds its tool result until release or its 30-second deadline. In `cancel` mode it forks a child that writes `child-ready`, waits, then attempts `child-late` on release while the parent waits for the child. Each line is the canonical operation UUID, one ASCII space, phase and LF. The marker is deliberately append-only without replay deduplication so duplicated effects remain observable. Use a fresh log and absent gate per subcase. Have a matching no-fault control show the expected bytes and child write before interpreting absence in a fault run.

Trigger a fault only after the observer reads the complete marker and sees the relevant process enter its gate wait after fsync, for example through a trusted syscall trace. Confirm that the terminal result has yet to be recorded and that the probe deadline is still live. Freeze a terminal timeout beyond the probe deadline so a terminal soft timeout cannot supply an early observation. The VM supervisor remains the outer hard stop. [Terminal timeout schema][terminal]

This probe supplies the effect and barrier. A trusted driver must control OpenHands HTTP/WebSocket traffic, save intent/receipt records, inject process and response loss, and collect independent observations. A coordinator-restart claim requires a durable control journal and a replacement process that reads it. A probe used with a one-shot client can only establish native executor behavior. The full harness, scripted Chat endpoint, and independent observers remain prerequisites.

## Recovery and escalation

| Situation | Proposed coordinator decision |
| --- | --- |
| Stop requested, old run may be alive | Persist pause/cancel/revocation and fence broker, dispatch and promotion using the current authority generation. Keep the attempt `Stopping` through an interrupt ACK. Capture actual process exit and host stop/reap, then reconcile already-issued effects and spend. An unproved stop blocks workspace reuse, new attempts and dependent admission. |
| Original operation proven delivered | Attach and observe under the recorded UUID. Close an operation receipt at most once using trusted delivery or effect evidence. A sealed, attributable candidate can proceed to verification under current approval. Use a recorded append as evidence of the original operation. A revoked or cancelled attempt can contribute audit evidence only. |
| Original mutation proven never delivered | Retry the eligible original operation once if the old sender is fenced, the approval is current, the exact intent is unchanged, and the original deadline and budget still allow it. A known failed task with stop, effect and settlement proof uses the separate correction budget and a fresh attempt, UUID and workspace. |
| Missing or conflicting evidence | Persist `Unknown outcome`, keep the fence and any financial reservation, and perform bounded read-only reconciliation. At the approved deadline, escalate once with exact identifiers, candidate/effect and spend uncertainty, evidence gaps, and acceptable dispositions. Keep the hold in place when a stale receipt arrives. No repeat append, message/run mutation, promotion or successor dispatch while the hazard remains unresolved. |
| Resume and dependency release | Keep same-conversation resume disabled pending qualified lookup, unchanged checkpoint and evidence bindings, stop/fence and clean pending-action state, known effects and spend plus current explicit authority. Handle confirmation through the explicit endpoint. Only current approved verification, independent review, integrated checks, guarded Git effect and durable acceptance can release T-02. |
